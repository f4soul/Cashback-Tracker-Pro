# Документация приложения Cashback Tracker Pro

## Обзор

**Cashback Tracker Pro** — мобильно-ориентированное PWA-приложение для учёта повышенного кэшбека по банковским картам. Позволяет консолидировать категории кэшбека всех своих банков на текущий период, хранить историю по месяцам, синхронизировать данные между устройствами через облако и экспортировать данные в PDF/Excel/PNG.

## 1. Архитектура проекта

### Композиция приложения
`App.tsx` — корневой компонент, отвечает только за layout (sidebar на десктопе, header + bottom-nav на мобильных) и композицию хуков. Вся stateful-логика вынесена в `src/hooks/`:

| Хук | Ответственность |
|---|---|
| `useAuth` | Слушатель Firebase Auth; до завершения первого резолва auth показывает «placeholder»-пользователя из кэша в localStorage — чтобы UI не дёргался при перезагрузке страницы для уже авторизованных. |
| `useCloudSync` | Две `onSnapshot`-подписки (профиль пользователя и коллекция месяцев), debounced-запись изменений в Firestore, импорт/экспорт полного JSON-бэкапа. |
| `useCashbackData` | CRUD над месячными данными, кастомными банками и категориями (локальный state + локальное хранилище). |
| `useThemeSync` | Применение тёмной/светлой темы и CSS-переменных кастомизации к `document.documentElement`, синхронизация `meta[name=theme-color]` для статус-бара iOS/Android. |
| `useScrollVisibility` | Скрытие/показ верхнего хедера и нижней навигации при скролле на мобильных. |
| `useLocalStorage` | Generic-хук персистентного состояния с debounced записью в `localStorage`. |

### Структура каталогов
- `src/views/` — экраны: `CurrentMonth`, `Archive`, `Settings`.
- `src/components/` — переиспользуемые UI-блоки: `CashbackTable`, `BankForm`, `BankLogo`, `MccDirectory`, `VersionHistory`, `ErrorBoundary`, `ui/Modal`, `ui/ConfirmModal`.
- `src/utils/` — чистые функции: даты (`date.ts`), сортировка категорий (`sorting.ts`), экспорт (`export.ts`), форматирование (`format.ts`), справочник МСС (`mccData.ts`), обрезка изображений (`cropImage.ts`).
- `src/constants.ts` — статичные справочники банков (`BANKS`, `BANKS_MAP`) и общих категорий (`COMMON_CATEGORIES`).
- `src/firebase.ts` — инициализация Firebase, обработка ошибок Firestore.
- `firestore.rules` — правила безопасности (owner-scoped доступ + email-allowlist администратора).

## 2. Основные разделы (вкладки)

### 2.1. Кэшбек (текущий месяц)

Центральный экран для управления актуальными данными.

- **Логика выбора периода:** приложение определяет текущий месяц автоматически. С 25-го числа текущего месяца по 5-е число следующего появляется переключатель периода — можно заранее заполнить данные на будущий месяц или вернуться к предыдущему, не уходя в Архив.
- **Два режима отображения:**
  - **Таблица** — компактная сводка всех банков с категориями и процентами, с переключаемой сортировкой категорий (по возрастанию/убыванию процента, сохраняется в localStorage).
  - **Список банков** — карточки с ручной сортировкой через Drag-and-Drop (`@dnd-kit`), поддержка мыши, touch и клавиатуры.
- **Управление банками:** добавление через плавающую кнопку (FAB) или из пустого состояния списка; редактирование и удаление существующих записей с подтверждением удаления.
- **FAB (плавающая кнопка добавления):**
  - На мобильных автоматически скрывается при скролле/взаимодействии с контентом, чтобы не перекрывать данные; восстанавливается отдельной мини-кнопкой.
  - Перетаскивается по вертикали, со «снаппингом» к трём позициям (верх/центр/низ области экрана); позиция запоминается между сессиями.
  - На десктопе (≥1150px) всегда видна, без скрытия и снаппинга.
- **Экспорт текущего месяца:** PDF, Excel (XLSX), PNG — кнопки в заголовке таблицы.

### 2.2. Архив

История всех сохранённых периодов, кроме текущего месяца, отсортированная от новых к старым.

- **Карточки-аккордеоны:** каждый месяц — раскрываемая карточка с компактной сеткой банков и встроенной таблицей. Несколько месяцев можно держать раскрытыми одновременно.
- **Поиск:** полнотекстовый, по названию банка и названию категории внутри месяца.
- **Фильтры:** отдельные выпадающие списки по конкретному банку и по конкретной категории кэшбека; применяются к содержимому всех карточек одновременно, скрывая месяцы без совпадений.
- **Экспорт по месяцам:** PDF, Excel, PNG — отдельно для каждой раскрытой карточки.
- **Удаление месяца:** полное удаление периода из истории с подтверждением (как из локального хранилища, так и из Firestore, если пользователь авторизован).

### 2.3. Настройки

Персонализация интерфейса и управление данными.

- **Внешний вид:**
  - **Акцентный цвет** — выбор из палитры или произвольный HEX. Управляет цветом кнопок, активных вкладок, акцентных бейджей через `var(--accent-color)`.
  - **Цвет блоков процента** (фон/текст) — отдельная настройка, отражается через `var(--percent-bg)`/`var(--percent-text)`.
  - **Цвет основного текста** — через `var(--app-font-color)`.
  - **Скругление углов (Border Radius)** — слайдер, управляет `var(--radius-app)`; применяется ко всем крупным контейнерам приложения (карточки, таблицы, модалки, панели) в реальном времени.
  - **Форма логотипов банков** — круг, квадрат (squircle) или прямоугольник — применяется глобально ко всем отображениям логотипов.
  - **Тема** — светлая/тёмная, синхронизируется в облако для авторизованных пользователей.
- **Инструменты:**
  - **Справочник МСС** — полнотекстовый поиск по базе MCC-кодов с описанием категорий операций; если код не найден локально — быстрый переход в поиск Google.
  - **История версий** — список изменений приложения по `public/versions.json` (доступно администратору).
- **Данные и бэкап:**
  - **Экспорт/импорт JSON** — полный бэкап всех данных приложения (настройки, история по месяцам, кастомные банки, категории, тема) одним файлом.
  - **Тестовые данные** — быстрое наполнение архива демо-данными для ознакомления с функциями.

## 3. Ключевой функционал

### 3.1. Банки и категории
- **Стандартные банки:** предзагруженная база популярных банков РФ с официальными логотипами (SVG) и фирменными цветами (`src/constants.ts`, `public/logos/`).
- **Кастомные банки:** добавление произвольного банка с собственным названием, цветом и логотипом — загрузка изображения с встроенным инструментом обрезки (crop) под выбранную форму логотипа.
- **Удалённые кастомные банки:** при удалении кастомного банка он переносится в «архив удалённых», чтобы исторические записи в уже сохранённых месяцах продолжали корректно отображать его название/цвет/логотип.
- **Категории:** общий список (`COMMON_CATEGORIES`) плюс пользовательские категории. Каждой категории назначается процент кэшбека в свободном текстовом формате (поддерживает значения вроде «до 10%»).

### 3.2. Синхронизация и хранение данных
- **Локальное хранилище:** все данные по умолчанию сохраняются в `localStorage` (debounced-запись, без блокировки UI на больших объёмах истории).
- **Firebase Firestore:** при входе через Google данные синхронизируются в реальном времени между устройствами.
  - Запись месяца — документ `months/{uid}_{monthId}`.
  - Настройки/кастомные банки/категории/тема — документ `users/{uid}`.
  - Все записи в Firestore — debounced и не происходят чаще, чем раз в 500ms на тип данных (`settings`/`month`), независимо от частоты пользовательского ввода.
  - Массовый импорт бэкапа — атомарный `writeBatch`, не последовательные одиночные записи.
- **Первый вход:** если в облаке нет данных, а локально они есть — локальные данные автоматически загружаются в Firestore (миграция «снизу вверх»), без потери истории.
- **Индикатор синхронизации:** визуальный значок в профиле пользователя на время активной записи в БД.
- **Защита данных:** `firestore.rules` ограничивает доступ владельцем документа (по `uid`) либо администратором (по email из allowlist), со схема-валидацией структуры записей.

### 3.3. Экспорт
- **PDF** — рендер таблицы в чистый документ без элементов управления, оптимизирован под печать/шаринг.
- **Excel (XLSX)** — структурированная таблица «Банк / Категория / Процент» для дальнейшего анализа, с автоподбором ширины колонок.
- **PNG** — карточка-изображение таблицы для отправки в мессенджеры.
- Во всех режимах экспорта элементы управления (кнопки сортировки/удаления/переключатели) скрываются, остаются только данные.

### 3.4. Адаптивность и PWA
- **Desktop:** постоянный боковой сайдбар, расширенная сетка настроек, таблицы с большим горизонтальным пространством.
- **Tablet:** адаптивная сетка (переход 2 колонки → 1 в зависимости от ширины), увеличенные touch-зоны.
- **Mobile:** нижняя навигация с авто-скрытием при скролле, плавающая кнопка добавления, полноэкранные модальные окна, поддержка safe-area (вырезы/индикатор домой на iOS/Android).
- **PWA:** устанавливаемое приложение (`manifest.json`, иконки, service worker через `vite-plugin-pwa`), корректная синхронизация цвета статус-бара с активной темой.

## 4. Модель данных

```ts
interface MonthData {
  monthId: string;          // "YYYY-MM"
  entries: CashbackEntry[];
}

interface CashbackEntry {
  id: string;
  bankId: string;
  customBankName?: string;
  customLogo?: string;
  customBankColor?: string;
  customBankLogoText?: string;
  categories: CategoryItem[];
}

interface CategoryItem {
  name: string;
  percent: string;           // свободный текст: "5", "до 10%" и т.п.
}

interface Bank {
  id: string;
  name: string;
  color: string;
  logoText: string;
  logoUrl?: string;
}

interface AppSettings {
  logoShape: 'circle' | 'square' | 'rectangle';
  accentColor: string;
  percentBlockBg: string;
  percentBlockText: string;
  fontColor: string;
  radius: number;             // px, управляет --radius-app
}
```

## 6. Безопасность

- Авторизация — только Google OAuth через Firebase Auth.
- Firestore доступ — `firestore.rules`: чтение/запись только владельцем документа (`request.auth.uid`) либо администратором по email-allowlist; схема входящих данных валидируется на стороне правил (`isValidUser`, `isValidMonth`).
- Любой путь, не описанный явно в правилах, запрещён catch-all правилом (`allow read, write: if false`).
