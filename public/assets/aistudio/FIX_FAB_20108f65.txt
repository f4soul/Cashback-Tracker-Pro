Фикс FAB — направленное скрытие вместо мгновенного
Роль: senior frontend-инженер. Проект: Cashback Tracker Pro (React 19 + TS + Tailwind 4 + motion/react). Работаем ТОЛЬКО с src/views/CurrentMonth.tsx (блок FAB). Ничего больше не рефакторим.

Контекст проблемы
FAB добавления банка автоматически скрывается обработчиком scroll-событий (сейчас — строки ~346-377): он ловит ЛЮБОЕ scroll-событие в capture-фазе и мгновенно ставит isFabHidden=true. Из-за этого: (а) guard через target.closest("#fab-container") никогда не срабатывает, потому что у scroll-событий target = document, у которого нет closest; (б) докатывающийся momentum после свайпа и программные scrollTo (смена таба, scroll-nudge темы) мгновенно прячут кнопку; (в) сразу после восстановления кнопки любое событие снова её прячет — пользователь физически не успевает нажать «+».

Шаг 1. Заменить эффект авто-скрытия (полностью удалить старый useEffect с handleInteraction и window.addEventListener("scroll", handleInteraction, true)) на:
const lastScrollYRef = useRef(window.scrollY);const fabHideLockedUntil = useRef(0);useEffect(() => {  const handleScroll = () => {    if (window.innerWidth >= 1150) return; // десктоп — FAB всегда виден    if (isFabHidden || isModalOpen || isDeleteModalOpen) return;    if (isDraggingFab.current || isDraggingRestore.current) return;    if (Date.now() < fabHideLockedUntil.current) return; // grace-period после восстановления    const y = window.scrollY;    const delta = y - lastScrollYRef.current;    lastScrollYRef.current = y;    // Прячем ТОЛЬКО при уверенном прокруте ВНИЗ.    // Микросдвиги, momentum вверх и программные scrollTo порог не проходят.    if (delta >= 24 && y > 120) {      setIsFabHidden(true);    }  };  // ВАЖНО: passive:true и БЕЗ capture — слушаем только страничный скролл,  // внутренние контейнеры (модалки, списки) скрытие не триггерят.  window.addEventListener("scroll", handleScroll, { passive: true });  return () => window.removeEventListener("scroll", handleScroll);}, [isFabHidden, isModalOpen, isDeleteModalOpen]);
Оба useRef объявить рядом с остальными ref'ами компонента (isDraggingFab / isDraggingRestore).

Шаг 2. Grace-period при восстановлении. В onClick ручки восстановления (motion.div id="fab-restore") после setIsFabHidden(false) добавить:
fabHideLockedUntil.current = Date.now() + 900;
Это окно, в течение которого докатывающийся momentum не имеет права спрятать восстановленную кнопку.

Шаг 3 (полировка, обязательна). Зона касания ручки. Сейчас видно ~20px — попасть сложно. Внутри motion.div id="fab-restore" первым ребёнком добавить невидимую hit-зону:
<div aria-hidden="true" className="absolute -inset-y-3 -left-6" />
Родителю (fab-restore) убедиться в наличии className с "relative" (он fixed — позиционированный, этого достаточно).

Красные линии (нарушать запрещено)
НЕ трогать: useScrollVisibility (шапка/навигация), Modal.tsx, useModalScrollLock, utils/scrollLock.ts, useThemeSync (включая forceThemeColorMeta и scroll-nudge), токены --accent-color/--percent-bg/--percent-text, apple-metas, sonner.
Физику пружин FAB и ручки (stiffness 400-450, damping 38, snap 3 позиций, localStorage fab_y_offset/fab_hidden) — сохранить как есть.
Drag-механику (drag="y", dragConstraints, isDraggingFab/isDraggingRestore с setTimeout 100мс) — не менять.
Самопроверка (обязательна)
npm run build — ноль ошибок TS, ноль новых warnings.
В коде не осталось window.addEventListener("scroll", ..., true) в CurrentMonth.tsx.
Порог и grace-period присутствуют: delta >= 24 и Date.now() + 900.
Smoke-тесты (мобильная ширина, iOS Safari)
Скролл вниз >24px → FAB прячется (прежнее поведение сохранено).
Скролл вверх → ручка остаётся; тап по ручке → FAB появился и НЕ исчезает, пока страница докатывается.
Сразу после восстановления тап по «+» → модалка открылась; после закрытия FAB на месте.
Смена таба (программный scrollTo top) → FAB не прячется.
Смена темы на проскролленной странице → FAB не прячется.
Драг FAB по вертикали → снап 3 позиций, позиция сохраняется после перезагрузки.
Ширина окна ≥1150 → FAB виден всегда, скрытий нет.
